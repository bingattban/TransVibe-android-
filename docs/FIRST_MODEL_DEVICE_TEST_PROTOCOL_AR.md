# بروتوكول قبول النموذج الأول: ggml-tiny.bin

لا تنفذ اختبار أي نموذج تالٍ قبل إتمام هذا البروتوكول والموافقة الصريحة.

### GitHub — اختبارات قبل بناء APK
- نجاح `TransVibe-so-` في اختبار JNI/Kotlin والبناء الفعلي؛ التحقق من ELF Android ARM64 وبصمة SHA-256 والاعتماديات.
- استيراد المكتبة في PR منفصل؛ مطابقة بصمة مصدر `whisper_jni.cpp` الفعلي.
- نجاح وحدة Android واختبارات Room والترحيلات والنسخ الاحتياطي وتوافق ملفات النماذج؛ نجاح Debug/Preview على SHA واحد.
- وجود ZIP كامل للمشروع قابل للفتح من Code On The Go.

### الهاتف — اختبار حقيقي وليس محاكاة
- بناء التطبيق باستعمال زر Build داخل Code On The Go.
- تثبيت Preview منفصلا عن التطبيق النهائي، والتحقق من نجاح تشغيل التطبيق ومنح الصلاحيات.
- استيراد النموذج الرسمي `ggml-tiny.bin` والتحقق من بصمته وحجمه.
- معالجة ملفات فيديو مرجعية ثابتة (قصير عربي، قصير إنجليزي، مختلط اللغة، أطول زمنيا) مع حفظ بصماتها محليا للمقارنة.
- قياس زمن استخراج الصوت، زمن ASR، الزمن الكلي، استهلاك الذاكرة، صحة النص والتوقيت، وحالات الإلغاء والانقطاع وعدم وجود نموذج.
- مشاركة سجل تشغيل حقيقي دون كلمات مرور أو بيانات خاصة؛ مقارنة النتائج مع النموذج السابق بعد اعتماده.
- توثيق أخطاء الأداء والاستقرار وإصلاحها قبل طلب الموافقة.

**حالة القبول الحالية: غير مختبر على الهاتف / غير معتمد.**
