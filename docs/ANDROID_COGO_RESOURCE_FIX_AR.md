# TransVibe — معالجة تعارض أيقونة التطبيق في Code On The Go

## الدليل من سجل الهاتف — 20 نوفمبر 2026

فشل `:app:mergeDebugResources` بسبب وجود **`ic_launcher.png` و`ic_launcher.webp` معا** ضمن مجلدات `mipmap-mdpi` و`mipmap-hdpi` و`mipmap-xhdpi` و`mipmap-xxhdpi` و`mipmap-xxxhdpi` في مشروع الهاتف `CodeOnTheGoProjects/C`.

هذا التكرار **غير موجود في أحدث `main` الذي تم فحصه**: المستودع يحتفظ بصور PNG الأصلية. لذلك لا داعي إلى استبدال الأيقونة أو حذف الملفات الأصلية في GitHub.

## طريقة المعالجة على الهاتف دون المساس بالتطبيق المثبت

1. احتفظ بنسخة احتياطية من مجلد مشروع Code On The Go الحالي بالكامل، وخصوصا `app/libs` وأي بيانات توقيع محلية. لا تحذف التطبيق المثبت ولا قاعدة بياناته.
2. الأفضل استخراج أرشيف GitHub النظيف في **مجلد جديد مستقل** وفتحه كمشروع جديد. **لا** تفك الضغط فوق المشروع القديم `C`، ففك الضغط فوق ملفات موجودة يترك ملفات WebP القديمة.
3. إذا تعذر تغيير مجلد المشروع: افحص `app/src/main/res/mipmap-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}/`. أبقِ `ic_launcher.png` الأصلي واحذف **فقط** `ic_launcher.webp` من كل مجلد يوجد فيه الملفان بعد النسخ الاحتياطي؛ ولا تحذف ملفات `ic_launcher_background.png` أو `ic_launcher_foreground.png` أو `ic_launcher_monochrome.png`.
4. أعد تنفيذ `:app:assembleDebug` وسجل أي أخطاء جديدة كاملة. حل تكرار الأيقونة لا يثبت نجاح الترجمة أو البناء النهائي، ولا يثبت تطابق تصميم كل شاشة.
5. إن توفر Python على بيئة أخرى، شغّل `python3 tools/check_android_resource_collisions.py` لفحص موارد المشروع دون أي تعديل. ويُختبر هذا الفاحص عبر مجموعة اختبارات المصدر في GitHub Actions.

## ضوابط الإصدار

- لا تدمج التغييرات في `main` قبل نجاح جميع الاختبارات وبناء إصداري Preview وRelease والتحقق من التوقيع. **طلب المراجعة Draft لا يسمح بالدمج التلقائي.**
- لا تُضمّن المفاتيح الخاصة أو نماذج الصوت أو سجلات المستخدم الشخصية في المستودع.
- المصادر الحالية تتضمن اختبارات للخطوط والألوان وصورة الترحيب والأيقونة. هذه الاختبارات **ليست** إثبات تطابق بصري 100% للشاشات: ذلك يحتاج لقطات مرجعية وقياسات مرئية على الجهاز.
