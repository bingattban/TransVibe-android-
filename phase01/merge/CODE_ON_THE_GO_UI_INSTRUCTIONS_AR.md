# تشغيل TransVibe من واجهة Code On The Go فقط

هذا المشروع يعتمد على أساس Code On The Go الذي قدمه مالك التطبيق في `TransVibe.zip`.

1. فك ضغط حزمة **TransVibe_CoGo_Base_Merged_Full.zip**. افتح مجلد `TransVibe` الذي يحتوي مباشرة على `settings.gradle.kts`, `build.gradle.kts`, `app/`, `gradle/`.
2. من واجهة Code On The Go اختر **Open Project** ثم هذا المجلد، وأكمل المزامنة Sync إن ظهرت.
3. افتح إعدادات البناء في التطبيق، وإذا كان الاختيار متاحا اختر **Preview** لتجنب المساس بالنسخة المثبتة من التطبيق. معرف Preview هو `com.transvibe.app.preview`.
4. اضغط **Build** من واجهة البرنامج العادية. **لا حاجة إلى أي أوامر طرفية أو سطر أوامر**.
5. إذا اكتمل إنشاء APK، ثبت نسخة **Preview** فقط إن كانت متاحة ثم افتح التطبيق وتحقق من الشاشة الرئيسية والتنقل. إذا كان المتاح Debug فقط، لا تثبته فوق تطبيقك الإنتاجي لأن توقيعه قد يختلف.
6. عند الفشل انسخ سجل البناء كاملا بما فيه `* What went wrong:` والسطور التي تبدأ بـ`e:` و`Caused by:`، ثم أرسله للمراجعة. لا ترسل كلمات المرور أو محتوى ملفات التوقيع.

## إعدادات لا ينبغي تغييرها تلقائيا

- المنتج: `TransVibe`. المعرف الإنتاجي `com.transvibe.app`.
- البناء: Gradle `9.6.1`, AGP `9.3.1`, Kotlin `2.3.21`, KSP `2.3.14`, Java target `17`, compileSdk `36`.
- `minSdk 26` و `targetSdk 35` احتفظنا بهما من التطبيق السابق لتجنب تغيير دعم الأجهزة والسلوك دون تحقق.
- رقم الإصدار `versionCode 6` من التطبيق السابق، وليس 1 من القالب الفارغ.
- يرفض Release البناء إذا لم تكن محركات Whisper وSherpa الحقيقية حاضرة، ولا يعتبر الجسر التشخيصي تعرفا صوتيا.

## ملفات التوقيع

لم تُدرج `release.keystore` و`release.properties` المرفقتان في المشروع الفارغ في حزمة التسليم لحماية مفتاحك وكلمات المرور. تبقيان لديك بشكل خاص، ولا تضعهما في GitHub أو ترفعهما للمحادثة. إذا احتجت لاحقا إلى إصدار إنتاجي، يجب استخدام مفتاح التوقيع المتوافق مع النسخة المثبتة. توجد `release.properties.example` بلا أي أسرار.
